# 1K/1K latency campaign, first cell (27 Sep 2026)

Gates were copied into `GATES_SNAPSHOT.md` before these runs. Both profiles
used the pinned vLLM 0.30.0 image, the local Quark MXFP4 checkpoint, O2
`FULL_AND_PIECEWISE`, TP=1, max length 16,384, chunked prefill 8,192, and
`scripts/bench_openai_stream.py` with input 1,024 / output 1,024.
`VLLM_ROCM_USE_AITER` stayed unset. Startup logged `AiterMxfp4LinearKernel`
on both. Attention was `ROCM_ATTN` (page 784) then
`ROCM_AITER_UNIFIED_ATTN` (page 832). Profiler instrumentation was off.
Each concurrency was warmed, then measured three times. Server
`num_requests_waiting` stayed 0. Client concurrency equalled the burst size,
so there was no extra client-side queue.

## Gate result for this cell

AITER passes throughput and TTFT. It fails the absolute 11 ms token-arrival
ceiling at C4 and C8. C1 passes.

| Cell | Stock, 3-rep mean | AITER, 3-rep mean | Gate | Result |
|---|---:|---:|---|---|
| C1 tok/s | 79.38 | 99.34 | ≥ 98 | Pass |
| C8 tok/s | 556.60 | 656.11 | ≥ 640 | Pass |
| C1 TTFT p95 | 61.3 ms | 62.2 ms | ≤ 67.4 ms | Pass |
| C4 TTFT p95 | 261.4 ms | 273.1 ms | ≤ 287.6 ms | Pass |
| C8 TTFT p95 | 457.9 ms | 425.5 ms | ≤ 503.7 ms | Pass |
| C1 ITL p95 | 13.36 ms | 10.13 ms | ≤ 11 ms and ≤ stock | Pass |
| C4 ITL p95 | 14.22 ms | 11.25 ms | ≤ 11 ms and ≤ stock | **Fail** (beats stock) |
| C8 ITL p95 | 14.77 ms | 11.97 ms | ≤ 11 ms and ≤ stock | **Fail** (beats stock) |

TTFT limits are stock plus the larger of 10% and 5 ms. Every AITER request
at C4 had ITL p95 between 11.24 and 11.27 ms, and every C8 request was
between 11.94 and 11.99 ms. The miss is the whole batch, not one stream.

## What kind of delay it is

| Question | Evidence |
|---|---|
| C1 first token? | No. C1 TTFT is 62 ms versus 61 ms, and C1 ITL p95 is 10.13 ms. |
| Server queueing? | No. Waiting requests stayed 0. The C8 maximum single gap is 70 ms on one interval; p99 stays 12.2 ms. |
| Periodic gaps? | No. p95 and p99 differ by about 0.3 ms at C4 and C8. |
| Late-decode tail? | No. AITER per-request p95 is 10.07 / 10.16 / 10.17 ms for the first 32, middle, and last 32 tokens at C1, and 11.88 / 11.91 / 12.24 ms at C8. |
| Concurrency-dependent steady step? | Yes. The median gap is already 11.12 ms at C4 and 11.79 ms at C8. |

Stock still shows the old context growth inside one request: C1 p95 moves
from 11.76 ms in the first 32 tokens to 13.70 ms in the last 32. AITER does
not.

## Decision

This cell is a targeted-fix candidate only for the steady C4/C8 decode step.
No scheduler, graph, or GEMM change was made. Stock `ROCM_ATTN` is the
production service. Raw rows are `rocm_attn_pass1/` and `aiter_unified/`.
